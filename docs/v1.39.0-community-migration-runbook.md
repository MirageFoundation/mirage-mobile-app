# Mirage v1.39.0 Community Migration Runbook

## Purpose

Migrate the Expo/React Native app to Mirage v1.39.0's permanent community model. The target removes all legacy topic and Agent-era contracts rather than relying on the temporary server shim.

This is an atomic protocol cutover. Do not send `X-Mirage-Visitor` from a partially migrated app because the presence of that header disables important legacy shim behavior.

## Execution Model

Implement this migration one bounded task at a time:

1. Delegate the task to `@plan` for a read-only review of current mobile code and the authoritative `mirage-node` implementation.
2. Require an implementation-ready handoff with exact files, symbols, contracts, tests, dependencies, and exclusions.
3. Delegate that bounded handoff to `@flash` for implementation and focused verification.
4. Review the outcome before starting the next task.
5. Keep the permanent contracts in this document current if implementation discovers a mismatch.

Authoritative implementation references are under the sibling `mirage-node` repository. Runtime mobile code and tests must not depend on that sibling repository.

## Confirmed Contracts

### Posts

Modern root posts use `community` at tag 101 and append protocol version `1` at tag 106 after all media fields.

Reference: `../mirage-node/shared/canon.py:118`.

Comments use an empty community. The chain rejects a reply with `legacy_thread_read_only` when its immediate parent's chain metadata is absent or its metadata community is empty. Protocol version `0` alone does not establish read-only eligibility: bridge-created protocol-0 posts can have valid metadata and accept replies. Missing protocol information is likewise not rejection evidence.

Preserve served `thread_locked` behavior independently. Record an explicit `legacy_thread_read_only` rejection against the actual parent and server, preserve the draft, and prevent repeat submissions to that parent. Do not infer a blanket thread restriction from a rejected nested parent or from protocol version alone.

References: `../mirage-node/blockchain/x/core/module/module.go:1565-1569` and `../mirage-node/tests/cases/test_backend_content.py:1473-1550`.

### Subscriptions

Modern subscriptions sign explicit `period_count` at tag 102. The valid range is 1 through 12.

Reference: `../mirage-node/shared/canon.py:569`.

Only level 1 is purchasable. The app must parse all three returned configurations because the Admin configuration defines limits, but the purchase UI exposes only Free and Subscriber.

Account-level mapping:

- `0` -> tier index 0, Free
- `1` -> tier index 1, Subscriber
- `>=100` -> tier index 2, Admin
- Any other level, including legacy `10`, is invalid or stale until signed status refreshes

Never expose an Admin purchase action.

### Signed reads

Signed reads use exactly:

```text
get_posts:<derived-address>:<timestamp>:<nonce>
get_comments:<derived-address>:<timestamp>:<nonce>
curator_read:<derived-address>:<timestamp>:<nonce>
```

References:

- Verification: `../mirage-node/web/backend/routes/core.py:779`
- Signed content read coverage: `../mirage-node/web/backend/routes/public.py:327`
- Timestamp validation: `../mirage-node/web/backend/routes/core.py:792`

Requirements:

- Timestamp is milliseconds.
- Proof validity is five minutes.
- Read proofs do not use the write-nonce replay table.
- Apply signed content reads to bootstrap, feeds, search, user posts, and comments.
- Apply `curator_read` to protected curator endpoints.

### Visitor and platform identity

Every Mirage request must include:

- stable anonymous `X-Mirage-Visitor`
- mobile `X-Mirage-Platform`

This includes native background uploads, retries, and server switching. Visitor identity survives login and logout.

Header presence, not a nonempty value, disables unsigned legacy behavior.

Reference: `../mirage-node/web/backend/legacy_mobile_wiring.py:203`.

Deferred campaign attribution uses:

```http
POST /api/stats/visitor_attribution
```

Accepted data includes `visitor_id`, platform, UTM fields, and `ref`. Retry sending the deferred `ref` until successful.

Reference: `../mirage-node/web/backend/routes/public.py:8578`.

### Community detail and served lens state

Community detail returns a valid response even when the slug has no posts or teams.

Reference: `../mirage-node/web/backend/routes/communities.py:305`.

The backend stamps each served post with:

```ts
lens: {
  requested: "effective" | "default" | "team" | "raw";
  effective_mode: 0 | 1 | 2;
  effective_team_id: number | null;
};
thread_locked: boolean;
```

Reference: `../mirage-node/web/backend/curation.py:611`.

Preserve these fields in mobile domain types and caches. Do not reconstruct them from local preferences. Use served values for lens labels, curator action eligibility, thread composer suppression, cache restoration, and deleted or unavailable pinned-team fallback.

### Lens parameters and temporary picks

Support:

- `lens=effective|default|team|raw`
- `team_id`
- `scope=current|legacy`

Aggregated feeds support normalized per-community choices:

```text
lens_picks=slug:default,other:raw,third:team:3
```

Parser reference: `../mirage-node/web/backend/routes/public.py:161`.

Requirements:

- Keep temporary choices for guests and unjoined communities in non-persisted session state.
- Cap temporary picks at 20.
- Sort and normalize the encoded value.
- Include normalized `lens_picks` in bootstrap, home, following, and search request identity and query keys.
- Clear a temporary choice after the user joins and persists a preference on-chain.
- Never persist temporary picks across app restarts.
- Invalid or deleted pinned teams fall back to the default lens.

Web reference: `../mirage-node/web/frontend/src/utils/curation.js:208`.

- Team deletion

### PoW and subscriber quota

PoW skipping depends on effective paid or Admin relay eligibility and daily quota, not merely `user_level > 0`.

The checked generic backend rejection classifier does not visibly expose that as a top-level structured `error_code`.

Reference: `../mirage-node/web/backend/chain.py:334`.

Before finalizing the mobile quota parser, add a node integration test that exhausts quota and records the exact HTTP response. Support the documented structured response, but verify it rather than inferring the final payload.

## Visitor / platform / attribution cutover

The mobile candidate now activates first-party `X-Mirage-Visitor` and `X-Mirage-Platform` plus deferred campaign delivery. Slices 1-9 remain in place. This is not a store release.

Implemented:

- Device-scoped visitor ID at `mirage_analytics_visitor_id` in MMKV (`src/services/visitor-identity.ts`). Identity is synchronous and available on the first/headless request; it does not depend on React providers, wallet, or Mixpanel.
- Shared header helper (`src/api/mirage-request-headers.ts`) applied by the dedicated ApiClient request interceptor for trusted Mirage API origins + `/api` paths only. Global Axios/fetch are unchanged.
- Standalone peer discovery uses `https://mirage.talk/api/get_peers` and attaches identity headers explicitly.
- Native `backgroundUpload` image/video retries run inside `apiClient.runExternalWrite`, reuse the captured server URL, reject stale generations, and send identity headers without a multipart `Content-Type` override.
- Previous-server push unregister uses `postTrustedAbsolute` so old-node cleanup is explicitly trusted.
- Deferred campaign acknowledgement is snapshot-safe (`capturedAt` + ref/UTM fields). Attribution POSTs `/api/stats/visitor_attribution` with `visitor_id`, `platform`, and optional bounded `ref`/UTM only. Success requires HTTP success and literal `ok === true`. Lifecycle is mounted under `ApiServerProvider` and is not awaited inside `afterCommit`.
- Persisted query v5 sanitizer strips additive `topic` / `root_topic` alongside Agent metadata on mixed valid modern posts. Schema stays at v5.

Mixpanel consent gating is unchanged. Signed read proofs continue to coexist with identity headers.

### Redirect transport follow-up (2026-09-05)

- ApiClient JSON GET/POST (including explicitly trusted old-server cleanup) and standalone peer discovery now use the installed Axios fetch adapter with a lazy, scoped `expo/fetch` injection. `Request: null` and `Response: null` avoid global RN Request/body conversion and Response stream wrapping. Native fetch receives `redirect: "manual"`; no global fetch or third-party transport changes.
- Installed Expo source forwards redirect mode in JS, disables both OkHttp `followRedirects` and `followSslRedirects` on Android for manual mode, and declines redirection in iOS `NativeResponse.swift`. This is the enforcement path, not Axios's Node-only `maxRedirects`/`beforeRedirect` options, which are not RN XHR enforcement.
- Every returned 3xx is rejected, including same-origin redirects and permissive `validateStatus` callers. ApiClient retries, default query retries, signed/curator read retries, inbox overrides, and native-upload retry handling treat returned 3xx as terminal. Initial destination trust and old-server cleanup trust are unchanged.
- Axios continues to own URL/query/body serialization, transformations, cancellation and timeout composition. The adapter settles HTTP status outside the installed fetch adapter because its `AxiosError.from` path drops a caught HTTP response. Errors retain the original config so retried JSON still decodes, and fetch `ETIMEDOUT` maps to the prior `ECONNABORTED` policy. Native body consumption remains covered by the composed signal; failed 3xx bodies cannot become retryable transport errors.
- Android compressor upload patch now disables normal and SSL redirects on its dedicated OkHttp client, preserving existing background uploads and 600-second timeouts. `bun install --offline --ignore-scripts` applied the existing patch workflow; `bun.lock` is unchanged and no dependencies were upgraded. A native rebuild is required to use the patch.
- **iOS architecture decision resolved with explicit user approval:** strict redirect protection takes priority over uninterrupted suspended/terminated uploads. The compressor patch now uses `URLSessionConfiguration.default`, not a background session. Apple's [redirect delegate documentation](https://developer.apple.com/documentation/foundation/urlsessiontaskdelegate/urlsession(_:task:willperformhttpredirection:newrequest:completionhandler:)) limits redirect vetoes to default/ephemeral sessions; a background-session delegate alone was never a solution. See the foreground upload follow-up and remaining device gates below.
- JS adapter tests exercise the installed Axios adapter and a separately mocked Expo fetch seam with the real ApiClient: JSON serialization, proof payload preservation, identity/third-party omission/old-server trust, all tested 3xx outcomes, network retry, timeout, cancellation, and server switch. Android patch application/source checks are not device enforcement tests.
- Native controlled 301/302/303/307/308 same-origin/off-origin/HTTPS-to-HTTP matrices remain **unrun**: no device/simulator plus controlled servers was configured. No claim of production readiness follows from JS tests or source inspection.
- Verification: `bun run test` (695 passing), `bun run lint` (clean), `bun run typecheck` (clean), and `bun run check:architecture` (passed, existing single file-size warning). The full compressor patch was reversed, clean-apply checked, and reapplied in a temporary copy of installed Android/iOS sources. Full working-tree `git diff --check` reports three pre-existing blank-EOF warnings in untouched API index/envelope files; scoped changed-file whitespace checks pass.

### Approved iOS foreground upload follow-up (2026-09-05)

- `patches/react-native-compressor@1.18.2.patch` retains Android's no-follow flags and timeouts and changes iOS to a controllable default session. Every proposed redirect is declined with `completionHandler(nil)`. A known 3xx is captured before cancelling response consumption so a slow/broken redirect body cannot become a retryable network timeout. The JS return shape remains `{ status, headers, body }`; rejected 3xx bodies may be empty. No redirected request is intentionally issued, including same-origin redirects.
- iOS task descriptions carry explicit upload UUIDs. A serial queue owns registration, cancellation and delegate state; per-UUID task/response/resolver records avoid colliding task identifiers across sessions. Completion removes the record exactly once, removes multipart files and invalidates its session. `UrlTaskManager` remains unchanged for other package uses; this uploader no longer relies on it or background configuration identifiers.
- Multipart is file-backed, written in 64-KiB chunks, retaining the generated boundary, `file` field, filename/MIME, `kind`, video metadata and initial Mirage headers. Response buffering is capped at 1 MiB. Body construction failures remove partial files; success/error/cancellation remove completed temporary bodies. Orphaned bodies are purged on the first multipart preparation in a new process, never replayed. This uses temporary disk space proportional to the upload size, not daemon-backed continuation.
- The patched Metro JS source uses the same abort listener for removal, rejects already-aborted signals before native upload, checks registration races, and exposes the cancellation ID only after enqueueing native work. Progress remains scoped by UUID. `backgroundUpload` retains its public name/API; media diagnostics now say `native-upload`, not `native-background-upload`.
- `runExternalWrite`, captured original-server URLs, generation checks and retry policy are preserved: images have at most two retries, videos none, and returned 3xx are terminal. No new relaunch recovery/rebroadcast mechanism is introduced. The previous implementation had no durable upload recovery journal; do not describe uninterrupted continuation as an established capability retained by this change.
- Existing iOS compose warning now says: "Keep Mirage open until the upload finishes. Uploads may stop if you lock or leave the app." Active-app operation is the supported contract. Background time, lock, suspension, system termination and force quit are **not guaranteed to continue or resume**. Returning to foreground is not evidence of upload success; only a valid server response completes the upload.
- Verification: 12 focused mocked/source tests and full `bun run test` (707 passing), `bun run lint`, `bun run typecheck`, and `bun run check:architecture` pass (existing one file-size warning). Bun patch generation and `bun install --offline --ignore-scripts` were run; generated `.bun-tag` artifacts were removed from the patch, and all three patched files passed temporary-copy reverse/clean-apply/reapply byte comparison. Package versions and `bun.lock` remain unchanged. iOS SDK Swift typechecking with minimal React bridge/event stubs is a compile check, **not a full native app build or runtime/device test**.
- Both platforms require native rebuilds; an OTA JS update cannot install these transport changes. Controlled device gates are in [native-upload-redirect-checklist.md](native-upload-redirect-checklist.md) and remain unrun. No live backend, upload, authenticated POST, deployment or commit was performed for this follow-up.
